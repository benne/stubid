# 2026.09.2

Every instance now serves an admin interface, there are two applications a reader can start,
and the public API is spelled in US English. What the emulator answers under `/op` has not
changed.

## What is published

The same seven packages and the same image as 2026.09.1. Three tags point at this release:

| Tag | Moves |
| --- | --- |
| `2026.09.2` | never |
| `2026.09` | to the next release in the same month |
| `latest` | to every release |

Pin `2026.09.2` in anything that asserts on bytes.

## The broker's bytes have not moved

This is the first release where the version of the build and the version of the recording come
apart. The build is 2026.09.2; the profile that names which sitting is being served still says
2026.09.1, because none was taken since. The emulated surface answers exactly what 2026.09.1
answered — the fidelity ledger and the divergence list are unchanged, and a suite asserting on
discovery, the key set or any token sees nothing new.

What did change is StubID's own surface: the control API under `/_stubid/v1` grew,
`POST /_stubid/v1/reset` clears more, and the public names are spelled differently. A dated
version says which recording you are running, which is why the profile keeps a version of its
own and will keep lagging this one until a release carries a capture.

## An admin interface

Every instance serves pages at `/_stubid/admin`, on whichever listeners it has. They show
logins arriving and let you decide them by hand, manage the citizens an instance signs in as
and the decisions queued against a client, list what it has handed out, and describe what this
build emulates — read from the routes it loaded and from the fidelity ledger in the attributes
on the code that emits each answer, rather than from a list maintained beside it.

A host inside your test process has no socket to open in a browser, so a `StubId.InProcess`
suite can reach the pages through its client but cannot watch one. Watching an instance by hand
means the container.

The logins table keeps itself current without a reload, and works with JavaScript switched off:
the server renders it, a Refresh link keeps your filters, and the line claiming it updates on
its own stays hidden when it would not be true. One consequence is worth knowing. StubID
expires a login by noticing rather than by a timer, so reading the list is what makes an expiry
happen — an instance somebody is watching expires parked logins promptly rather than whenever a
test next looks. Under a controllable clock nothing moves unless a test moves it.

A decision made on a page goes through the same code as one made through the control API, and
the ladder records which door it came through. The issued page never shows the value of a code
or a token, not even a prefix.

**There is no password on any of it**, and no setting that adds one. That is deliberate and
written down in `docs/guides/admin.md` rather than left to be discovered: the boundary is the
port. One consequence is new. These pages are forms, so a page you merely visit can now add a
citizen, queue a decision, re-point the address this instance answers as, and move the clock on
an instance started with a controllable one. Before, `POST /_stubid/v1/reset` was the only
control route reachable that way, because it takes no body and the rest of the control API
refuses a plain form.

## What a test can read and set

Ten routes, each with a typed client method:

| Route | For |
| --- | --- |
| `GET /_stubid/v1/clients` | the three clients this instance accepts |
| `GET /_stubid/v1/routes` | the routes the profile loaded |
| `GET /_stubid/v1/issued` | pushed requests, codes and access tokens, never their values |
| `GET /_stubid/v1/time` | what the clock says, and whether it can be moved |
| `GET /_stubid/v1/citizens/{id}` | the route `POST /_stubid/v1/citizens` had always named in its `Location` |
| `PATCH /_stubid/v1/citizens/{id}` | the one field worth changing while something runs: the rule |
| `GET`, `DELETE /_stubid/v1/behaviors` | read the queue without spending it, or empty it |
| `GET`, `PUT /_stubid/v1/runtime/automatic-approval` | park logins for one test and hand it back |

The last is an override in front of the `StubId:ApproveAutomatically` setting —
`StubId__ApproveAutomatically` in a container's environment — rather than a write to it, which
is what makes "back to how this instance started" something you can ask for.

`GET /_stubid/v1/sessions` and `GET /_stubid/v1/sessions/{id}` carry two more members.
`oauthError` is the other half of the pair a refusal sends: a refusal puts `errorCode` in
`error_description` and this in `error`, and only one of them could be read back from a session.
`version` moves once per transition, so a caller can tell one read of a login from the next; it
has nothing to do with the version of this release. Both are additions, so nothing that read the
old payload breaks.

## Applications you can start

`samples/aspnetcore` is a stock ASP.NET Core application that signs in against a container — an
application a reader can run rather than read. It is not decoration: a test hosts that same
`Program.cs`, not a copy, on every change, and a second test proves the pinning is real by
replacing the check with one that accepts anything, which leaves the login green and is noticed
by nothing else. A refused login now gets a page naming the `error` and `error_description`
StubID sent, where it used to get a blank 400.

The Node sign-in moved from `tests/` to `samples/node` and now defaults to the port the image
publishes. `docs/guides/signing-in.md` is the shortest path from nothing to a page of claims,
and routes you to whichever of the four client stacks is yours. It also says plainly that the
Spring check resolves metadata and does not sign in, which the previous release note got wrong.

`docs/guides/testcontainers.md` stops claiming that a first run with no image builds one. The
module has never been able to build an image; a first run pays for a 53 MB pull instead, which
is the number to budget for a cold CI runner.

## Two instances against one key directory

They could disagree about their own keys. `File.Move(overwrite: false)` is not atomic on Unix:
it checks whether the destination exists and then calls rename, which replaces it silently. Both
starts find the file missing, both write, and the second's rename overwrites the one the first
has already read — leaving the first holding a key that is on nobody else's disk and in no file.
Measured rather than inferred: two threads racing a single destination both reported success in
1,476 of 20,000 attempts. The keys and the self-signed TLS certificate are now written and read
under an exclusive handle on a lock file, so each is written once and never replaced. The
certificate mattered as much as the keys, because two instances sharing a volume have to serve
the same one or a client that pinned what the first handed out cannot reach the second.

One cost comes with it. The lock is taken before the key file is looked for, so the key
directory now has to be writable even when the keys are already in it — a read-only volume that
worked in 2026.09.1 fails at startup here. A `.pfx.lock` file stays beside each key afterwards,
on purpose: deleting it would be its own race.

## Breaking

**Spelling is US English throughout.** The repository was written in British English and is now
written in American English, which is what the surrounding ecosystem already uses. Eight names
that shipped in 2026.09.1 changed with it:

| Was | Is |
| --- | --- |
| `BehaviourApi` | `BehaviorApi` |
| `StubIdClient.Behaviour` | `StubIdClient.Behavior` |
| `StubIdHost.Behaviour` | `StubIdHost.Behavior` |
| `StubIdContainer.Behaviour` | `StubIdContainer.Behavior` |
| `BrokerState.OrganisationOf` | `BrokerState.OrganizationOf` |
| `Client.Organisation` | `Client.Organization` |
| `PublicBaseUrl.TryNormalise` | `PublicBaseUrl.TryNormalize` |
| `POST /_stubid/v1/behaviours/enqueue` | `POST /_stubid/v1/behaviors/enqueue` |

Seven of the eight still work as they were. The old member names are `[Obsolete]` aliases that
forward to the new ones, and the old route is registered a second time onto the same handler, so
an existing suite compiles with a warning rather than an error and keeps answering over the wire.
**Those aliases go away in the release after this one**, which is the whole point of their being
here.

`BehaviourApi` is the exception: the type itself is gone rather than deprecated, because an alias
for it would have meant unsealing the class that replaced it. Code that only reaches the property
— `stub.Behaviour.EnqueueAsync(...)`, which is what the guides showed and what most suites write
— is unaffected. Code that names the type needs `var` or the new name.

One smaller edge: `Client.Organisation` is a read-only alias, so reading it works and
`with { Organisation = ... }` needs the new name.

Arguments passed by name moved too. `Tokens` takes `organization` where it took `organisation`,
in `IdToken`, `UserInfo`, `UserInfoToken`, `TransactionToken` and `Subject`; `PublicBaseUrl.Set`
takes `normalized` where it took `normalised`; and `Client`'s third positional parameter is
`Organization`. Positional calls are unaffected; only a caller naming one of those arguments has
to change.

No JSON field name that ever shipped changed, and the admin interface, the issued-artifact reads
and the queue reads all arrived after 2026.09.1 and have never been in a package or an image, so
they simply carry the new spelling.

**Three shapes in `StubId.Server` gained a required member, with no alias behind them.**
`IssuedCode` and `IssuedAccessToken` each take a `LoginId` in fifth position, and
`BrokerState.IssueCode` takes the `loginId` that supplies it. That is what ties an issued
artifact back to the login it came from, which is what the issued page lines its entries up by,
and there is no way to add it and keep the old shape. `StubId.Server` is substrate — published
because the three packages a suite references depend on it, not because anything is meant to
call it — so this should reach nobody. Code that does construct either record, or call
`IssueCode`, has to pass the new argument. `StubIdSession` also gained `OauthError` and
`Version`, but both are optional and appended, so only a positional deconstruction notices.

**`POST /_stubid/v1/reset` clears more than it did.** It cleared the sessions and the queue; it
now also clears issued codes, access tokens, pushed requests and the CPR-match counters. A reset
that left credentials standing was surprising, and the issued page is where somebody first
notices. Citizens still survive a reset, which is the thing suites depend on.

## Not changed on purpose

The recorded fixtures keep their British spelling. Their `meta.json` files are hashed into a
manifest, and the session pack's manifest records a sitting that cannot be repeated — so the
spelling in a recording is part of the record rather than prose to be corrected.
